ねこみたい・NEKOMITAI

Nekomitai Blueprint.

A web browser that lives inside After Effects — watch reference videos, browse the web, and pull colors and assets straight into your comp. With an optional adblocker and anti-tracker.

Made by Akamine Izuna X @Izuna_text Buy Me a Coffee github.com/hignode/nekomitai Plan v1.2 — August 25, 2026 · M1 shipped, spikes green
01 · Verdict

Feasible — with three hard walls we design around

This plan is grounded in verified research (Adobe CEP 12 docs, CEF maintainer statements, license texts, competitor teardown — all checked August 2026). The product is buildable and the niche is empty: no shipping tool combines in-AE browsing, video reference, adblock, and asset import. But three platform walls are physically unbypassable, and the architecture below is shaped by them.

CONFIRMED  Platform: CEP 12

After Effects 25.0–26.0 supports CEP 12 panels (embedded Chromium 99 + Node.js 17.7.1). UXP panels do not exist for AE as of 2026, so CEP is the only option — and it's confirmed working. H.264/AAC, VP9, and Media Source Extensions all work, so YouTube's embed player plays video fine.

WALL 1  Sites can refuse to be framed

X-Frame-Options / CSP frame-ancestors are enforced in CEF's network layer; no CEP flag disables them. youtube.com's watch page refuses framing.

Design answer: a local Node "Gateway" proxy that strips those headers for general sites, plus official embed players (youtube-nocookie, Vimeo, Twitch) for video — those are built to be framed.

WALL 2  No DRM, no Google login

CEP's Chromium has no Widevine and can't get one → Netflix-type sites will never play. Google login blocks embedded browsers.

Design answer: scope these out explicitly; a one-click "open in system browser" escape hatch covers them.

WALL 3  No live playback sync, no drag-out

comp.time freezes during RAM preview, and drag-from-panel-to-timeline works in Premiere but not AE.

Design answer: scrub-sync (playhead lock while scrubbing/paused — same as Frame.io's panel) and one-click import buttons instead of drag.
02 · Architecture

Three layers, one gateway

Everything is one CEP extension with three layers. The Panel UI (what you see), the Gateway (a Node.js server on 127.0.0.1 that does all networking: proxying, adblocking, downloading, embed resolution), and the Host bridge (ExtendScript that touches the AE project). Every feature routes through these three — the full connection map is in section 04.

Browsing works in three tiers

TierWhatHowReliability
Video Mode YouTube, Vimeo, Twitch, Dailymotion, SoundCloud (full tracks) + direct media URLs + local files. Spotify links play via its embed player — previews only: full-track web playback needs Widevine DRM, which CEP lacks (Wall 2); full control comes via Spotify Connect (see Logins card). Any pasted/clicked watch URL is converted (oEmbed lookup from Node) to the provider's official embed player: youtube-nocookie.com/embed/…, player.vimeo.com, player.twitch.tv?parent=localhost. These endpoints are built to be framed. RELIABLE
Web Mode Arbitrary websites — docs, articles, portfolios, reference boards, image search Gateway fetches the page server-side, strips X-Frame-Options / CSP framing headers, rewrites URLs, runs the adblocker, injects cosmetic filters, serves it to the iframe from localhost. A server-side cookie jar in the Gateway plays "the browser" for cookies, so logins on normal sites work and persist (big-tech SSO still refuses embedded browsers — see Logins card in §05). BEST-EFFORT — heavy app-sites (full YouTube, X, Google login, PWAs) will break; expectations set in UI
Escape hatch Anything the panel can't render (DRM, logins, broken sites) One-click "Open in system browser", offered automatically when a page fails. ALWAYS WORKS

Why the view surface is served from localhost, not file://. Twitch embeds hard-require a real hostname in their &parent= check, cookies behave better with an http origin, and several providers check the embedding hostname. So the page that hosts the content iframe is itself served by the Gateway at http://127.0.0.1:<port>/view. The Gateway binds loopback only, picks a free port at startup, and requires a per-session token on every request so no other local app (or webpage) can use it.

Security stance (important for a browser-in-a-panel): web content is hostile by default. The content iframe is sandboxed, never gets Node access (--mixed-context is deliberately NOT enabled), and everything privileged (filesystem, downloads, ExtendScript) lives in the outer panel and Gateway only. Proxied pages lose clickjacking protection by design, so the UI always shows the true URL of the page being viewed.

04 · The connection map

Every root, route, and mapping — connected

Three route tables (UI, Gateway, ExtendScript), then the end-to-end map that ties every feature through all three layers.

A — Panel UI routes hash router in App.tsx

RouteScreen
#/browserMain browsing surface: tab strip, omnibox, back/forward/reload, shield (adblock) indicator, view-surface iframe. Default route.
#/playerReference player: transport, frame step, A/B loop, speed, sync-to-AE controls, marker list. Opens automatically when a tab resolves to a video.
#/boardsBookmarks and reference boards with thumbnails; boards can be linked to the current AE project.
#/downloadsDownload queue with progress; per-item "Import to AE" / "Add to comp" actions.
#/settingsTabs: General · Adblock & Privacy (both OFF by default, opt-in) · Sync · Advanced.
#/aboutVersion + update check, credits (Akamine Izuna · X · Buy Me a Coffee), open-source licenses.

B — Gateway HTTP routes 127.0.0.1:<port>, token-authenticated

RouteMethodDoes
/view?target=<url>GETServes the view-surface page for a tab. Decides tier: video → embed iframe, general site → proxy iframe, known-broken → escape-hatch card.
/embed/resolve?url=GETWatch-URL → embed-URL via per-provider rules + oEmbed/noembed fallback. Returns {provider, embedUrl, title, thumb, videoId}.
/proxy/<enc-url>GET/POSTWeb Mode. Fetches target, strips X-Frame-Options/CSP framing, rewrites HTML/CSS URLs back through /proxy/, applies adblock network filter, injects cosmetic CSS + true-URL banner.
/adblock/statusGETEnabled flags, list versions, blocked-count for the session (feeds the shield badge).
/adblock/configPOSTToggle adblock / anti-track; enable or disable individual filter lists.
/adblock/updatePOSTRe-fetch EasyList/EasyPrivacy (48h auto-cadence too), rebuild + reserialize engine cache.
/downloadPOSTQueue a URL → saves into USER_DATA/Nekomitai/cache/, returns {id, path}.
/download/:id/eventsGETSSE progress stream for the queue UI.
/auth/:providerGETOpens the provider's official OAuth page in the system browser; Gateway listens on /auth/callback (loopback redirect) and stores the API token. Powers YouTube/Vimeo account features via their official APIs — never an in-panel Google login page.
/cookiesPOST/DELETEPower-user cookies.txt import into the proxy's jar; "clear all site data". Jar is stored permission-restricted (encrypted where the OS allows).
/sessionGET/POSTPersist/restore open tabs, per-tab history, settings (JSON in USER_DATA).
/healthGETLiveness + version, used by panel boot.

05 · Features

What no in-AE browser has

The only comparable shipping product (YouWatch, $0+ on Gumroad) opens a YouTube window and nothing else. Frame.io syncs playback but only for its own hosted media. Every feature below is unserved inside After Effects today.

🎯 Reference player with timeline scrub-sync

Lock the video to your comp's playhead (with offset), frame-step, A/B loop, speed control. What Frame.io does for its own media — for any YouTube/Vimeo/local video. Honest limit: sync is scrub/paused, not during RAM preview (AE physically can't).

🛡️ Adblock + anti-tracker (opt-in)

@ghostery/adblocker engine over EasyList + EasyPrivacy in the proxy path, cosmetic filtering injected into pages, referrer stripping and third-party-cookie blocking. Off by default, one toggle, live blocked-counter badge.

📥 Send to AE

Right-click any image/video/GIF on a page → downloads via Node → auto-imports into a "Nekomitai" bin → optional add-to-comp. (Drag-out to the timeline is impossible in AE — Premiere-only API — so this is one click instead.)

🎨 Color & palette grab

Eyedropper any pixel of a page → new solid or recolor the selected layer's Fill. Extract a 5-swatch palette from any image into solids. (EyeDropper API exists in Chromium 99 — verified in spike M0.)

📌 Timestamp markers

One click drops a comp marker holding the video URL + timecode + note. Click a marker entry in the panel to jump the video back there. Reference notes that live in the comp itself.

🗂️ Per-project reference boards

Bookmarks with thumbnails, grouped into boards keyed to the open .aep — open a project, get its references back. Plus full session restore of tabs.

🌗 AE-native feel

Dockable panel, UI palette derived live from AE's own appearance setting (appSkinInfo + theme-change events), keyboard-friendly omnibox.

🔐 Logins that actually work

Three mechanisms: a Gateway cookie jar makes normal-site logins work in Web Mode; "Sign in with YouTube / Vimeo" runs official OAuth in your system browser and unlocks your subscriptions, playlists, and search inside the panel (played via embeds — ToS-clean); and Advanced settings takes a cookies.txt import. Spotify gets the same OAuth treatment plus Spotify Connect: browse your playlists/library in the panel and remote-control your running Spotify desktop app (play/pause/seek; Premium required) — the ToS-clean answer to CEP having no DRM. Google/Microsoft SSO pages inside the panel stay impossible — they detect embedded browsers by policy.

🔄 Update check

In-panel check against GitHub Releases; opens the download page when a new version exists (silent self-update isn't possible for ZXPs).

Explicitly out of scope (platform walls, not laziness): DRM sites (Netflix & co. — no Widevine in CEP, ever), full youtube.com site (embeds instead), Google/Microsoft SSO pages inside the panel (system-browser OAuth covers account features instead), live sync during RAM preview, drag-out to timeline, downloading YouTube videos (ToS violation and a distribution-channel killer — "Send to AE" targets directly-served files, not streamed video).

06 · Adblock, privacy & licenses

Legal-clean by construction

ComponentLicenseUse
@ghostery/adblockerMPL-2.0 OKUse unmodified; ship MPL text + source link in THIRD-PARTY-NOTICES and the About screen.
EasyList + EasyPrivacyCC BY-SA 3.0 OKFetched at runtime (48h cadence, honors the lists' 4-day expiry, bundled fallback snapshot). Attribution: "The EasyList authors (easylist.to)".
uBlock Origin codeGPL-3.0 EXCLUDEDCode cannot be reused (copyleft). Ideas and filter syntax are fine — the Ghostery engine already parses uBlock syntax.
Peter Lowe's listnon-commercial EXCLUDEDForbids anything money-adjacent — this is why we do NOT use Ghostery's prebuilt engine bundle (it includes this list) and compose our own list set instead.
DuckDuckGo / Ghostery tracker DBsCC BY-NC-SA EXCLUDEDNon-commercial only. Anti-tracking derives from EasyPrivacy + proxy behaviors (referrer strip, 3P-cookie block, GPC header) instead.

Two legal notes to stay aware of: (1) A July 2025 German court ruling reopened the question of ad-blocker legality in Germany (Axel Springer v. Eyeo, still pending) — one more reason the blocker ships OFF by default, as a user choice. (2) Blocker or not, we never market Nekomitai as a "block YouTube ads" tool — embeds via youtube-nocookie are simply the clean way to watch.

08 · Open questions for Izuna

Your call before we start

NAME  "Nekomitai" collides with nekomitai.net

An established anime-download site owns the name's search results and social handles. No registered trademark found, but the piracy adjacency could hurt with Adobe/aescripts reviewers.

Recommendation: keep the name if you love it (no legal blocker found), but consider a qualifier for stores — e.g. "Nekomitai Browser". Your call.

SCOPE  Ship order

Plan ships Video Mode + AE features (M2–M3) before general Web Mode (M4), because video reference is the reliable core and Web Mode is best-effort.

Recommendation: agree to this order — an early usable beta after M3.

DIST  Donation model

Buy Me a Coffee link lives in #/about and on the website for the free GitHub build; on aescripts the equivalent is Name-Your-Own-Price (their norm — external donate buttons are not).

Recommendation: free on GitHub + NYOP on aescripts.

LANG  UI languages

English-only first, or English + Japanese from day one? The string layer will be i18n-ready either way.

Recommendation: EN first, JA at M6.

Nothing gets built until you say "Agree". Reply with any changes — scope, names, feature priorities — and the plan gets revised first.
